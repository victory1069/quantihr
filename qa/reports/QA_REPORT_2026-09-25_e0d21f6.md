## 2. Executive Summary

Phase 2 adds the repository's first CI workflow (INF-02) and a coverage
measurement baseline (INF-01) for `packages/shared` and `apps/api`. No product or
application code and no test code was changed. The first live CI run **failed**:
the existing `schema-drift.test.ts` reads an old `ddl.sql` from git history, which
wasn't present in GitHub's default shallow checkout. That finding (FND-CI-001) was
reproduced, classified as an environment/configuration issue, and fixed in the
workflow (`fetch-depth: 0`) without touching the test. The second live run
(36141102729) **passed** on Node 22.11.0: shared 181/181, api 349/349, coverage
matching the local baseline, and a 521,442-byte coverage artifact uploaded. The
main limits are that `apps/mobile` is not in CI, that EBADENGINE warnings from the
mobile dependency tree are unresolved, and that it has **not been verified** whether
`master` requires this CI check before merging. **QA status: SHIP WITH CONDITIONS**
(§3). This is a QA assessment only and does not authorize a merge.

## 9. Test Strategy

- **Risk and depth:** INF-02 is P0. A broken or falsely green gate would silently
  let regressions into `master`. So the gate was tested on both paths: it must pass
  on good code and fail on bad code (framework §5, §7). INF-01 is P1: verify that
  measurement happens and is reproducible; no threshold behaviour to test.
- **Modes (framework §4):**
  - *Structural:* workflow schema validation, diff/file-list review, lockfile
    review, config inspection.
  - *Runtime (local):* a clean-checkout simulation of every workflow step, plus
    injected failures.
  - *Runtime (CI):* live GitHub Actions runs, which are the only evidence for the
    pinned Node version and the real checkout.
  - *Hybrid:* overall. The workflow was checked structurally, simulated locally,
    then verified live.
- **Success looks like:** CI green on HEAD with the expected counts; coverage
  produced and uploaded; numbers reproducible between local and CI.
- **Failure looks like:** a CI step failing on correct code; a gate passing on
  broken code; coverage numbers differing between environments.
